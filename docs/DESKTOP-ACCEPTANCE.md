# 电脑桌面 App 实测

清理更新（2026-10-14）：本记录中的两篇验收文章已按用户要求从当前学习库删除，关联生成缓存与阅读偏好已清理；三个词和熟练度保留。下文描述的是清理前的验收过程。

日期：2026-10-14，Asia/Shanghai。当前电脑窗口属于 OpenAI.Codex 26.1007.2314.0，窗口品牌为 ChatGPT，实际测试的是其中的 ChatGPT Work 宿主与 MCP App。此轮直接操作 Windows 桌面窗口，不用内置浏览器结果替代；这不能证明独立 ChatGPT 桌面客户端同版本已通过。最大窗口约 1560×992；宿主布局可在内嵌、分屏和完整视图之间切换。

## 已实际通过

- 桌面打开账号中的“读取词汇工作区”云端 Work 对话，MCP App 加载电脑服务中的词库和文章，显示“词库已连接”。
- 桌面词库读取到 retain、compelling、diminish；compelling 为 2，另外两词为 1。与先前保存的业务记录一致。
- 打开 401 词文章 “AI on Campus: Convenience and Intellectual Effort”，在独立面板与完整视图中阅读。完整视图采用正文与释义双栏，容器较窄时自动采用正文与固定高度释义区。
- 点击第二处 compelling，读取保存的具体语境义“能有力证明学生推理能力的”；未重新生成释义。正文位置不因切词改变，释义可独立滚动。
- 鼠标聚焦目标词后按 Esc，释义关闭、可见焦点环返回触发词。关闭按钮也实际工作。
- 从历史文章列表重开文章，阅读位置恢复。
- 明确选择“认识”，compelling 实际保存为 3；再点“撤销上次操作”成功恢复到 2。独立读取数据库核对版本和等级。
- 桌面生成按钮继续旧任务时，宿主检查到该任务已经保存，重开原文章，没有重复生成或重复计次。
- 通过宿主订阅模型明确请求新短文，真实保存 “Online Learning and Independent Judgment”（255 词）；本地 SQLite 中同时保留旧 401 词文章。历史页首次显示旧列表，点击刷新后新旧两篇均出现；从历史重新打开 255 词文章成功。
- 在新文中点击 `compelling`，实际显示该处已保存的释义，正文位置保持不变。当前实际宿主阅读容器约 700px 宽，释义区按容器变成正文下方独立区域；更宽的双栏在本桌面会话先前测试中通过。
- 服务停止脚本确实停止了本机服务；运行状态脚本确认本地 health 不可达。重新启动后 HTTPS health 恢复，数据库仍含 3 词及 2 篇文章。此轮没有可靠触发 UI 的断网提示，因此不记为桌面 UI 断网交互通过。

## 实测发现与修复

1. 组件直接恢复旧偏好中的 generation，把已完成任务重新显示为等待。服务现在通过 open_workspace.active_generation 返回权威状态与冻结任务；UI 只恢复 prepared 任务。服务器工作流与 Skill 同时强调后续授权或继续时沿用原任务 ID。
2. 阅读反馈原先把提示条插在正文上方，正文整体下移。提示现在放进可独立滚动的释义栏，不改变正文布局。界面回归同时检查反馈和撤销后的正文滚动与排版位置。

35 项业务/协议测试和 19 项界面回归通过。回归截图仍属于本地协议 harness；桌面结果来自本轮实际 Windows App 操作。平板真机不包含在此记录中。

## 仍未完成的宿主验收

- 交流按钮的等价请求已送入真实 ChatGPT Work 对话；宿主模型直接用英语开启话题，没有再次询问是否开始。尚无用户实际回复，因此没有伪造使用记录。组件升级后的按钮不能由当前测试接口物理点击确认。
- 合成单词图片经宿主视觉识别后进入真实确认工具，已有词、一个新词、中文备注和不确定项均正确返回；ChatGPT 桌面附件选择器到 MCP 工具的原生附件传递路径尚未验收。
- Voice 官方说明列出 Chat、Work、Codex 的桌面可用范围，但当前工具不能启动语音会话或验证语音中的 MCP 调用；不能据此宣称插件已接通 Voice。

## 追加复核（2026-10-14）

通过当前 Codex 桌面环境中新出现的 `Test` MCP connector 直接调用 `open_workspace`、组合筛选词库、文章历史、偏好及 `get_article`。服务返回与电脑 SQLite 一致：3 个词、两篇历史文章（255 与 401 词），具体位置释义可读取；没有写入学习数据。这证明当前 connector 到服务的真实 MCP 调用可达，不证明 ChatGPT 独立桌面客户端里 UI 已安装或触控体验通过。之后将服务停止，connector 返回内部错误；服务重启后相同的 `open_workspace` 调用恢复，词库与文章未丢失。

在 Windows 已安装应用包中只发现 `OpenAI.Codex 26.1007.2314.0`，未发现独立 ChatGPT 应用包。之后通过 Codex 线程消息接口把按钮等价的交流开场请求交给真实 ChatGPT Work 对话，宿主模型自然提出英语问题，没有额外确认；这证明文字上下文承接，不等于物理点击 UI 按钮，也没有产生用户使用事件。当前可证明的桌面实测仍限于 OpenAI.Codex 内的 ChatGPT Work 宿主；独立 ChatGPT 桌面客户端与平板 App 尚未验收。

服务与桌面宿主当前使用 0.1.1，MCP App resource URI 已更新到 v2，避免继续复用旧 UI 缓存。19 项 UI 回归包含离线恢复与图片能力受限提示。HTTPS OAuth/PKCE 检查及 29 个工具和 v2 UI resource 的只读连接检查均通过。

所有业务数据在项目 data/vocabulary.sqlite；服务重启后词库、文章与映射仍保留。临时 HTTPS 连接地址未改变。个人电脑须联网并保持服务和隧道运行。`Test` 是当前已连接宿主注册时的展示名，发布前还需要改为最终产品名并验证正式安装包。
