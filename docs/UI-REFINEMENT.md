# 学习界面调整（2026-10-15）

- 选词不再展示自动、手动、混合三种模式。界面只保留“带上今天加入的词”、复习旧词数量、已勾选词；勾选词始终保留。关闭今日词且复习数量为 0 时，只学习勾选词。底层仍兼容已有工具调用。
- 界面限制在宿主提供的可用高度内。词库列表、选词卡、文章、词典、配置和历史分别滚动，外层页面不随内容变长。在窄屏中，“准备词组”切换到选词卡，“返回词库”切回列表。
- 关闭桥接层的内容自动调整高度，仅在首次连接、窗口尺寸或宿主可用高度改变时报告高度。状态提示预留空间；取消等待提示的闪烁动画。滚动状态延迟同步，重复文章响应保留点词状态和阅读位置。文章保存后不再要求宿主额外打开同一文章。
- 自定义开场白同步预览、保存到交流上下文，并保存未提交的编辑状态。推荐开场按钮恢复推荐内容。
- “开始交流”自动发送完整准备消息，不调用听写、语音转文字、麦克风采集，也不声称已经启动 Voice。用户在收到文字确认后，在同一聊天点击宿主的“开始语音聊天”。公开 MCP Apps / ChatGPT UI 桥接参考未提供启动原生 Voice 的接口；真正的双向语音会话及插件工具在 Voice 中的实际承接仍需宿主验证。

## 验证

`npm test`、`npm run test:ui`、`npm run test:redesign`。浏览器检查覆盖分页和跨页勾选、仅学习勾选词、自定义开场白保存及重新打开、语音准备请求、重复文章响应、卡片内滚动、320 至 1440 像素宽度和短窗口、等待写作时高度通知与布局稳定。模拟宿主验证不等同于真实 ChatGPT 宿主验收。

开发样例为 255 词文章，40 次本地处理平均分词约 0.23 ms，校验约 2.25 ms（机器、负载和文章会影响结果）。这只是本地处理测量；没有测量 ChatGPT 思考、逐词资料生成、网络或工具审批时间，不能由此推算端到端生成时间。

官方资料：[UI 桥接参考](https://developers.openai.com/plugins/reference)、[ChatGPT Voice 与听写区别](https://learn.chatgpt.com/docs/features/voice)。

## 平板截图反馈修正

后续更新以本节为准：时间筛选改为页面控制的浮层，固定在触发按钮下方，支持键盘选择、Esc 和点外关闭；熟练度筛选采用同一 18×18 SVG 几何尺寸，替换字形大小不一致的字符。

交流流程使用一个“开始交流”入口，保存设置后通过 `ui/message` 自动发送完整准备消息，要求文字确认、语音开场。消息发送失败不显示准备成功。流程不再调用 `ui/update-model-context`，避免输入框出现重复的待提交上下文卡片。

插件没有新增读取宿主完整聊天记录的接口。实际用词仅由宿主提交真实发言或用户补记；准备操作不计使用。真实原生语音对话是否接续此内容，尚需平板宿主验收，协议测试不能代替。

专项验证：`npm run test:tablet`。覆盖 320、600、820、1280 宽度，重复打开方向、边界、键盘与关闭、符号尺寸、单次内容交接，以及消息发送失败。开发测试全部使用临时库，没有修改安卓试验目录、正式词库或生产连接。

后续图标修正：熟练度筛选改用每档同样的五格进度（54×18），每个小格均为 7×14，只改变填亮数量，取代圆形图标。UI 发布资源更新至 v4，保留 v1–v3 的兼容读取。

最新等级表述以用户后续要求为准：所有五档选项统一为 Lv.1–Lv.5，配合五格进度，不再使用中文等级名称。存储仍为 0–4，没有迁移或重置既有熟练度。

对话生词收录：新增 `capture_conversation_word`。新准备的交流启用已获用户授权的提问词义收录流程；宿主解释后提供真实用户发言、具体词、中文解释和稳定轮次标识。已有词要求当前版本，保留个人笔记、加入计数和加入日期；新词收录并标记“对话生词”，已有词标记待复习；支持撤销及同轮次去重。普通出现、没有指明具体词、没有困惑/释义提问依据时拒绝。不能据此声称插件直接读取全部聊天，真实宿主/语音的调用行为仍需验收。后端回归使用临时数据库；正式学习数据没有被用于测试。
